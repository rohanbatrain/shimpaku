Independent project · Junos lab · agent-first

Shimpaku

A Mist-style assurance system for a seven-device vJunos lab. It turns streaming telemetry into service levels, isolates a fault's blast radius, and lets an AI agent propose a fix, but never apply one on its own.

Open the dashboard Source and evidence What went wrong

The public dashboard is a read-only replay recorded from the live lab. The switches are never reachable from the internet.

The write path is the product

  1. ProposeAn agent (Claude Code, OpenCode, or the built-in assistant) calls an MCP tool.
  2. GuardrailsTen checks in Python, over live device facts, not prompt rules.
  3. Human approvalOnly a dashboard session can approve. It is not an MCP tool.
  4. commit confirmedPer-device lock; confirmed only after a fresh health check. If the executor dies, Junos rolls back.
  5. ValidateThe symptom is watched for a window. If it comes back, the action is marked recurred.

What it is, and is not

BuiltDeliberately not built
Service levels in probe-minutes, with n beside every percentageWi-Fi capacity SLEs: virtual radios report no retries
Blast-radius isolation with a significance gateLSTM anomaly detection: a rate test beat it on false alarms (simulated data)
One MCP server as the only path to a device, hash-chained auditAny connection to a real Mist account, its data or its look
A fault benchmark whose ground truth the system cannot readA scored detection result, which is the next milestone
